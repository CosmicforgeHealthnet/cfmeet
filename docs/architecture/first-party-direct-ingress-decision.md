# Decision record: first-party apps use direct service ingress, not the API Gateway (FE-018)

**Finding:** FE-018 (P3, INFRASTRUCTURE): "First-party apps bypass the API Gateway; 59 web
operations are intentionally absent from the gateway manifest". Blueprint v1.0 Section 16.
**Status:** accepted, 2026-11-07. Records audit decision D-01/D-02 ("confirm the browser API
origin and the gateway vs meeting-service contract").
**Disposition:** documented decision (`NOT_APPLICABLE_WITH_EVIDENCE`). It is not
`DEPRECATED_WITH_MIGRATION`: nothing is deprecated by this record and no client has to move.
The one EXCLUDED class that *is* being retired, `LEGACY_DIRECT_INGRESS` (the `/api/v1` surface),
has its own deprecation records (PLT-004
[legacy API keys](../api/legacy-api-keys-deprecation.md), MTG-017 / DATA-008 legacy meeting
writes, PLT-003 legacy webhooks) and follows owner decision D-9 (removal only after measured
zero consumers).

## Context

* The CF Meet web app and mobile app call the services on their own ingress:
  `NEXT_PUBLIC_API_URL=https://api.cfmeet.com/api/v1` (v2 is derived by replacing `/api/v1`,
  `apps/web/src/services/v2/api.ts`; `docs/ENVIRONMENT.md`). Calling is reached through the
  web app's server-side proxy (`/api/calling/*`, `apps/web/src/app/api/calling/[...path]/route.ts`).
* The API Gateway (`services/api-gateway`, ADR 0055) is the ingress for **customer
  applications**. Its routable surface is generated by `scripts/contracts/public_api.py`
  from the source contracts plus the explicit allow-list `infra/api-gateway/public-routes.json`
  into `infra/api-gateway/route-manifest.json` (default deny: an operation that is not
  classified fails CI). It is not deployed (PLT-005;
  [activation checklist](../operations/developer-platform-gateway-activation-checklist.md)).
* The gateway authenticates `PLATFORM_CREDENTIAL` (`cfmk_…`) for third-party traffic. For the
  meetings and Communications families it also accepts `MEETING_SESSION` /
  `PARTICIPANT_TOKEN`, so most first-party v2 meeting calls *could* transit it later; the
  operations below can not, by design.

## Decision

1. First-party apps keep **direct ingress** to the owning services (`api.cfmeet.com` → Meeting
   Service; the web server-side proxy → Calling). This is intentional, not a bypass.
2. The API Gateway is the ingress for third-party applications holding platform credentials
   (and Developer Platform console sessions). The SDKs (`@cfmeet/platform-sdk`,
   `cfmeet_platform_sdk`) target the gateway.
3. An operation that only first-party apps (or a private authority) may call is classified
   `EXCLUDED` with a reason code in `public-routes.json`. It never appears in the gateway's
   routable `routes`, and the gateway answers 404 for it. Reclassifying an operation is a
   public API decision reviewed like code.
4. The list below is generated from the allow-list and checked in CI
   (`python3 scripts/contracts/first_party_ingress.py --check`, Contracts workflow). It can't
   drift from the gateway manifest.
5. A future cutover of the web or mobile app to the gateway origin is a separate, owner-approved
   change. It must keep direct ingress (or add first-party routing) for every operation below.
   Pointing the apps at the gateway as-is would break sign-in, account, organization and
   messaging-bridge flows.

## Why

* The first-party BFF routes (`FIRST_PARTY_APP_BACKEND`, `FIRST_PARTY_SESSION_DEVICES`,
  `FIRST_PARTY_ORGANIZATIONS`, `FIRST_PARTY_APP_ACCOUNT`) act for the app's own signed-in user
  with a server-derived acting principal. Exposing them to customer credentials would create
  a second, unscoped messaging/organization API next to the canonical customer APIs.
* The legacy `/api/v1` surface (`LEGACY_DIRECT_INGRESS`) is deprecated; advertising it to new
  customers through the gateway would extend its life.
* `CONTACT_VAULT_PRIVATE` operations accept raw telephone numbers and are served only by
  Privacy Relay with a Contact Vault access token (see the
  [CAL-013 handoff](../api/privacy-relay-contacts-upstream-handoff.md)).
* `MEDIA_PLANE_DIRECT` traffic is latency-sensitive device↔media-edge traffic.
* `CALENDAR_FILE_DIRECT_INGRESS`: the gateway route grammar has no file-extension segments.

## The audit's "59 web operations"

The audit matched 188 web v1/v2 calls against the gateway manifest (point in time,
`docs/audits/cfmeet-frontend-backend-coverage.md`): 129 present, 59 absent, all of them in the
excluded classes (`LEGACY_DIRECT_INGRESS`, `FIRST_PARTY_APP_BACKEND`,
`MEETING_DIRECTORY_NOT_PUBLIC_FAMILY`). The count of web calls per class changes whenever the
web app changes. It is reported, not enforced, on every Contracts run by
`scripts/contracts/web_contract_parity_report.py` (FE-015, report-only, `apps/` belongs to the
frontend team). The authoritative, enforced list is the full EXCLUDED set below, which includes
non-web operations (Privacy Relay contacts, media plane).

## Consequences

* No code or routing change. `api.cfmeet.com` upstreams are unchanged.
* `infra/api-gateway/README.md` stays "LOCAL ONLY" until PLT-005.
* Frontend: nothing to do for FE-018. The related client work is FE-015 (SDK/generated-type
  adoption) and CAL-013 (Contact Vault upstream).
